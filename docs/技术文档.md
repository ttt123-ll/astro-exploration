## 1. 项目概述

### 1.1 项目背景

天文科普存在两个现实矛盾：一是优质内容分散在百科、新闻、图集、视频等不同形态中，普通用户难以按「我关心的问题」组织信息；二是通用大模型在垂直领域容易编造术语与数据，而科普场景对事实准确性要求极高。

「宇宙探索」以**天文科普 + AI 问答**为核心，把 20 余个内容模块与一个可溯源、可降级的 RAG 智能助手整合在同一个 Web 应用中：用户既能系统浏览内容，也能直接用自然语言提问，并获得带来源标注的回答。

### 1.2 项目定位

| 维度 | 说明 |
|---|---|
| 目标用户 | 青少年、天文爱好者、科技馆/教师等科普工作者 |
| 核心价值 | 内容体系化 + 问答可溯源 + 断网可用 + 对话可解释 |
| 技术特征 | 前端 AI Native 交互、混合检索 RAG、三级能力降级、离线部署 |
| 交付形态 | Docker 离线包 / 免安装演示包 / 在线 Web |

### 1.3 主要成果

- 20+ 页面：首页、太阳系、天文百科、四季星座、星空图集、宇宙时间线、近地天体、深空天体、科普视频、宇宙新闻、互动社区、探索工具、AI 助手、账号体系、后台管理等。
- RAG 知识库：52 篇文档、149 个知识块，混合检索 Hit@1 90%、Hit@3 100%、MRR 0.950。
- 全站 500+ 自动化断言（15 套测试脚本），覆盖接口、AI、UI、移动端、无障碍与浏览器走查。
- 三种部署方式：Docker 离线包（含 MySQL）、免安装演示包（内置 Node 运行时）、源码运行。

### 2.3 差异化分析

与「内容站」和「通用 AI 问答」相比，本项目的差异点：

1. **可溯源**：回答中的【n】角标可回到具体来源卡片与原文页面。
2. **可解释**：深度推理模型展示「思考过程」，回答标注能力级别（知识库/大模型/深度推理）。
3. **可降级**：站点 Key 不可用、用户 Key 失效、断网等场景逐级降级，AI 始终可用。
4. **垂直定制**：多受众讲法（入门/进阶/儿童）、观星装备导购（预算约束推理）、页面导航动作。

## 3. 系统架构设计

### 3.1 总体架构

```
┌──────────────────────────── 浏览器（Vue 3 SPA / PWA）────────────────────────────┐
│  页面视图 20+  │  AI 助手（SSE 流式）  │  3D（Three.js）  │  账号/社区  │  移动端 Tab  │
└───────────────┬───────────────────────────────────────────────────────────────┘
                │ HTTPS / SSE
┌───────────────▼──────────────────── Express 应用 ───────────────────────────────┐
│  安全中间件（Helmet/CSP/CORS/限流/访问日志）                                       │
│  路由层：auth / chat / news / scores / messages / neo / admin / misc              │
│  AI 层：意图识别 → RAG 检索 → Prompt 组装 → LLM/规则知识库 → 流式输出              │
│  RAG 层：知识切片 149 块 → 1024 维哈希向量 → 混合检索（词法 0.62 + 向量 0.38）      │
│  数据层：MySQL（用户/成绩/留言/新闻/访问） + 本地向量索引（.local-index.json）      │
└───────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 前端架构

- **技术栈**：Vue 3.5（`<script setup>`）+ Vite 5 + Vue Router 4 + Pinia + Axios + Three.js 0.186。
- **分层**：`views`（页面）、`components`（可复用组件）、`store`（Pinia：auth/ui）、`composables`（移动端/滚动等）、`data`（内容与知识源）、`utils`（时间/流式工具）。
- **设计系统**：统一 CSS 变量（色彩、圆角、阴影、字体）、`PageHeader` 页头组件、共享 `.info-card` / `.page-back`、导航与页脚组件。
- **AI 交互**：整页 AI 助手 + 全局聊天挂件，均走 `utils/streamChat.js`（SSE 解析 + 非流式降级），支持打字机、思考过程折叠、来源卡片。
- **性能优化**：路由懒加载、视频 `preload=none`、图片懒加载、构建期 Brotli/Gzip 预压缩、PWA 缓存。

### 3.3 后端架构

- **技术栈**：Node.js 20+ / Express 4 / mysql2 / JWT / bcryptjs / nodemailer。
- **安全**：helmet + CSP（禁用 `upgrade-insecure-requests` 以适配局域网 HTTP）、同源 CORS、全局与认证限流、参数化 SQL、JWT 版本号（退出即失效）、邮箱验证码 HMAC 哈希入库。
- **AI 服务**：`server/chat.js` 负责 Prompt、模型切换、流式解析、工具/动作；`server/rag/*` 负责索引构建与检索；`server/aiKey.js` 负责用户 Key 校验。
- **降级链**：DeepSeek → 站点 Key 失效提示 → 本地规则知识库（27 条规则 + 检索拼接）；RAG 内部再分语义向量/词法向量。

### 3.4 数据模型

| 表 | 用途 | 关键字段 |
|---|---|---|
| users | 用户 | username(unique)、password_hash、email(unique)、role、token_version |
| password_resets | 找回密码验证码 | email、code_hash、expires_at、used、attempts |
| scores | 测验成绩 | user_id、category、pct、duration_sec |
| messages | 留言板 | user_id、username、content |
| news | 新闻 | tag、title、summary、img、source、published_at |
| visits | 访问统计 | path、ip、created_at |

### 3.5 技术选型理由

| 选择 | 理由 |
|---|---|
| Vue 3 + Vite | 组合式 API 利于 AI 流式状态管理；构建快、生态成熟 |
| Express + MySQL | 轻量、部署简单；关系数据契合用户/成绩/新闻 |
| 自研本地哈希向量 | 无外部依赖、离线可跑、149 块规模下检索稳定；便于降级 |
| SSE 而非 WebSocket | 单向流式、与 HTTP 鉴权/代理兼容，部署成本低 |
| Docker 离线包 | 比赛环境网络不确定，离线可复现 |

## 4. AI 技术方案（核心）

### 4.1 总体 AI 架构

一次 AI 问答的完整链路：

```
用户问题
  → 意图/受众识别（月相、观星、装备、导航、知识问答）
  → RAG 混合检索（1024 维哈希向量 + 词法 TF-IDF）
  → 相关性过滤（MIN_RELEVANCE = 0.26）
  → Prompt 组装（系统人设 + 受众讲法 + 检索证据 + 多轮上下文）
  → LLM（deepseek-chat / deepseek-reasoner）或本地规则知识库
  → 流式输出（meta → reasoning → delta → done）
  → 前端渲染（打字机、来源角标、思考过程折叠、级别标签）
```

### 4.2 知识库构建

- **来源**：站内结构化内容（`client/src/data/*.js`）与图文详情，经脚本切分为 52 篇文档、149 个知识块。
- **切块策略**：按语义段落切分，块长 200-500 字，保留标题与来源路径，确保引用可回到原页面。
- **向量化**：自研 1024 维哈希 TF-IDF（中文 bigram + 关键词加权 + 维度哈希），无需外部 Embedding 服务，离线可用。
- **索引**：构建为 `.local-index.json`，随镜像分发；启动时加载，避免运行时依赖网络。

### 4.3 混合检索策略

综合得分公式：

```
score = 0.62 × 词法得分(TF-IDF / bigram) + 0.38 × 向量余弦相似度
```

- 词法通道保证术语、专有名词（如「参宿四」「M87*」）精确命中；
- 向量通道缓解同义表达与语序差异；
- 低于阈值 0.26 的知识块被过滤，减少无关证据干扰；
- 去重后取 Top-K（默认 4-6 块）进入 Prompt。

**检索评测**（149 块知识库，30 条标注查询）：

| 指标 | 结果 |
|---|---|
| Hit@1 | 90% |
| Hit@3 | 100% |
| MRR | 0.950 |

### 4.4 Prompt 设计

- **人设**：固定角色「星穹」，统一开场、语气与边界（仅回答天文相关问题、科学争议问题必须说明「目前科学界尚无定论」）。
- **受众分档**：入门（类比优先）、进阶（给公式与参数）、儿童（短句与比喻），通过不同系统提示词实现同一问题的三种讲法。
- **证据约束**：要求优先使用检索片段，使用【n】角标引用；资料不足时明确说明。
- **输出结构**：结论先行 → 关键参数 → 理解成本/延伸问题，兼顾可读性与信息密度。
- **安全边界**：超范围问题礼貌引导回天文；对伪科学/阴谋论不展开。

### 4.5 大模型集成

- **接口**：OpenAI 兼容协议调用 DeepSeek（`/chat/completions`）。
- **流式**：`stream: true`，服务端转换为 SSE：`meta`（级别/来源/工具）→ `reasoning`（推理模型思考）→ `delta`（正文）→ `done`。
- **模型切换**：`deepseek-chat`（极速）与 `deepseek-reasoner`（深度推理）；推理模型自动合并 system 消息、不传 temperature、超时放宽至 120s。
- **BYOK**：用户可在「AI 连接设置」填入自己的 Key，服务端校验余额/模型可用性后按请求头 `X-AI-Key` 使用；Key 只存本地浏览器，不落库。
- **可观测**：回答元信息标注实际模型、级别（大模型生成/深度推理生成）、来源数量。

### 4.6 AI 安全与可控性

| 风险 | 措施 |
|---|---|
| 无 Key / Key 失效 | 三级降级到本地规则知识库，保证可用 |
| 模型编造事实 | 检索证据约束 + 角标溯源 + 事实校订回归测试（深空场面积/创生之柱/参宿四等） |
| 提示词注入 | 系统提示与用户内容分离；仅允许白名单动作（页面导航/装备建议） |
| 敏感信息 | 站点 Key 仅存服务端环境变量；用户 Key 只在请求期使用 |
| 内容安全 | 超范围拒答、科学争议声明、输入长度限制与限流 |

### 4.7 Prompt 与回答示例

**示例问题**：创生之柱真的被摧毁了吗？

**检索证据**：来自「鹰星云 - 创生之柱」知识块（相似度 0.41），包含 2007 年超新星冲击波假说。

**回答要点**（节选）：

> 结论：目前没有定论。2007 年有研究推测，约 6000 年前一次超新星冲击波可能摧毁了这些柱子，但该假说仍有争议，尚未成为定论。由于光行时间延迟，我们看到的仍是它们约 7000 年前的样子。【1】【2】

- 回答先给结论，再给依据与不确定性，最后附来源角标；
- 对「是否被摧毁」这类科学争议，明确使用「推测 / 有争议 / 尚未定论」措辞，避免把假说写成事实；
- 该行为已纳入 	ools/verify-content-facts.js 回归测试，防止内容与 AI 复述出现事实错误。

### 4.8 Function Calling 与 Agent 工作流

除「检索问答」外，AI 助手具备**工具调用（Function Calling）**能力：先由大模型规划需要哪些工具，服务端执行后把结果作为证据注入最终回答，形成「规划 → 工具执行 → 生成」的最小 Agent 工作流。

| 工具函数 | 能力 | 实现 |
|---|---|---|
| `moon_phase` | 指定日期月相、月龄、照亮比例、观星指数 | 本地天文算法（无网络） |
| `tonight_sky` | 当季星座方位、天文暮光、最佳观测窗口 | 本地天文算法 + 星座数据 |
| `gear_advice` | 按预算与用途推荐望远镜/双筒/相机方案 | 装备规则引擎（预算约束） |
| `search_knowledge` | 在站内知识库检索可溯源片段 | 混合检索（词法 + 向量） |
| `navigate_page` | 生成站内页面跳转动作 | 路由映射 + 详情节 |

**流程**：

1. 命中工具相关意图（月相/观星/装备/检索/导航/日期等）时，发起一次短 `tools` 规划请求（`tool_choice: auto`）；
2. 解析 `tool_calls`，逐个执行本地工具，收集结构化结果；
3. 将工具结果作为「已展示给用户」的证据注入最终 Prompt，避免重复复述；
4. 流式生成最终回答，SSE `meta.toolsUsed` 与 `done.toolsUsed` 携带调用记录，前端显示工具徽标；
5. 推理模型不支持 tools 时自动跳过规划，规则工具兜底；无 Key/断网时仍可离线使用工具。

> 该能力同时覆盖评分表中的「Agent/工作流设计」与「MCP/工具集成」考察点；后续可把工具层迁移为 MCP Server，实现标准协议接入。

### 4.9 AI 交互体验

- 打字机效果（约 16ms/字）+ 闪烁光标，`prefers-reduced-motion` 下自动关闭动画；
- 推理模型展示可折叠「思考过程」，避免长文阻塞阅读；

## 8. 总结与展望

### 8.1 已达成

- 完整可运行的 AI Native Web 应用，覆盖内容、AI、3D、社区、账号与部署；
- RAG 有量化评测，AI 有降级与安全边界，工程质量有测试保障。

### 8.2 不足

- 检索仍为哈希向量，缺少语义 Embedding 与真实向量数据库；

- 缺少公网在线演示地址（可选加分项）。

### 8.3 规划

1. 接入 bge-small / 云端 Embedding + sqlite-vec/FAISS，补充消融实验与召回/时延对比；
2. 将 Function Calling 工具层迁移为 MCP Server，支持多步工具规划与外部数据源；
3. 增加多模态能力（图片问答/星空照片识别/语音输入）；
4. 前端渐进式 TypeScript 化，完善组件单测与覆盖率；
5. 部署公网演示环境，提供评审专用账号。
